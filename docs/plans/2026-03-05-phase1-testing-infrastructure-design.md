# Phase 1: Testing Infrastructure Design

**Date:** 2026-03-05
**Status:** Approved
**Phase:** 1 of 3 (Testing → Translation → Simplification)

## Goal

Build the testing foundation that will validate our Python executable specification against OpenVM's Rust implementation. No Python implementation code is written in this phase — only test infrastructure and golden vectors.

## North Star

Comprehensive end-to-end verifier tests. Everything else exists to support incremental progress toward this goal.

## Deliverables

1. **Test vector extraction** — Rust code that instruments stark-backend and OpenVM to capture intermediate values as JSON
2. **Rust verification tests** — Tests that load vectors and verify they match the live Rust code
3. **Python test stubs** — Scaffolded `executable-spec/` with failing tests that import the same vectors

## Approach: Bottom-Up Vector Extraction

Build the test vector pipeline incrementally, layer by layer:

1. Primitives layer — field ops, Poseidon2, NTT, Merkle tree
2. Protocol layer — FRI folding, constraint evaluation, proof stages
3. E2E layer — full proof artifacts from guest programs (Fibonacci, then increasingly complex)

At each layer: extract vectors → write Rust tests that verify them → write Python stubs that load them and fail.

## Test Vector Capture Strategy

### In stark-backend (external dependency)

- Add a `capture-test-vectors` Cargo feature flag
- When enabled, serialize intermediate values to JSON on stderr (following pil2-proofman's pattern)
- Captured values: FRI folding intermediates, Merkle commitments, constraint evaluations, challenge derivation, transcript state

### In OpenVM (this repo)

- Create a test-vector generation crate or test harness
- Exercise the prover/verifier on small guest programs
- Programs: Fibonacci first, then graduated complexity for proof system coverage
- `generate-test-vectors.sh` at repo root builds with the feature flag, runs programs, collects JSON into `executable-spec/tests/test-data/`

## Test Hierarchy

Following SPEC_STYLE_GUIDE Chapter 7:

### Critical tests (must always pass)

- E2E verifier: Python verifier accepts proofs generated by OpenVM Rust prover
- Binary equivalence: Python prover output matches Rust prover output byte-for-byte

### High-value tests (catch bugs early, localize failures)

- BabyBear field arithmetic (add, mul, inverse, extension field ops)
- Poseidon2 hash (known input → known output)
- NTT/INTT round-trip and known-vector equivalence
- Merkle tree construction and opening verification
- FRI folding at each round against golden intermediates
- Constraint evaluation against golden values

### Stubbed for Phase 1

All Python tests start as stubs that load vectors and `assert False` (or `pytest.skip("Not yet implemented")` is NOT acceptable per AGENTS.md — tests that don't pass must fail, not skip).

## Scripts (at repo root)

- **`setup.sh`** — Install Python dependencies (numpy, pytest, pytest-xdist). One-time setup.
- **`build.sh`** — Build any FFI components (e.g., Poseidon2 FFI if needed later).
- **`generate-test-vectors.sh`** — Build stark-backend with capture flag, run test programs, collect JSON vectors into `executable-spec/tests/test-data/`.
- **`run-tests.sh`** — Run pytest with named filters (`e2e`, `primitives`, `fri`, `all`) and parallel execution (48 workers per AGENTS.md).

## Test Programs for Vector Generation

Starting simple, graduating complexity:

1. **Fibonacci** — Small trace, exercises basic STARK pipeline
2. **Memory-intensive program** — Exercises memory bus interactions
3. **Extension-heavy program** — Exercises multiple chip types for proof system coverage

We use existing OpenVM test programs from `extensions/rv32im/tests/programs/examples/` where possible.

## Reference Implementation

pil2-proofman's executable-spec (at `/home/cody/openvm/pil2-proofman/executable-spec/`) serves as our reference for:
- Test infrastructure patterns (conftest.py, fixture loading, run-tests.sh)
- Vector format (JSON with metadata, inputs, expected sections)
- Binary proof comparison approach
- Parallel test execution with pytest-xdist
