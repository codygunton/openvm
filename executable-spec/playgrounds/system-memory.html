System: Memory Subsystem

OpenVM's memory consistency is enforced by two cooperating AIR chips. The VolatileBoundaryAir bookkeeps all touched memory locations, recording their initial and final values. AccessAdapterAir<N> handles block-size conversions — splitting a large block into smaller pieces or merging small blocks into a larger one. Together, they ensure every read returns the most recently written value.
View
VolatileBoundaryAir
One row per touched memory address, sorted by (addr_space, pointer). Each row records initial_data (always 0 for volatile memory) and the final_data + final_timestamp from the last access. It sends the initial state at t=0 and receives the final state, closing the memory bus loop.
AccessAdapterAir<N>
Converts between memory block sizes. Split (is_split=1): receives parent block of N values, sends two child blocks of N/2 values each. Merge (is_split=0): reverses the direction. The direction flag flips send/receive roles. Timestamps must satisfy: for split, both children share the parent timestamp; for merge, parent_ts = max(left_ts, right_ts).
End-to-End Memory Consistency
Instruction chips read/write memory via the memory bus. Each access receives the previous state and sends the new state. The boundary chip initializes (sends at t=0) and finalizes (receives at final_ts). Access adapters bridge block sizes. If all bus sends balance all receives, memory is consistent.

Memory Bus Balance

The boundary chip sends initial tuples and receives final tuples. Instruction chips (not shown here) send/receive for each access. All sends must match all receives for the bus to balance.

What to try

Change a final_data value. The boundary chip will still send the original initial state and receive the modified final state. If no instruction chip wrote that modified value, the bus won't balance.

Change a final_ts to be less than or equal to a write timestamp. The timestamp ordering constraint would fail in the full system (here you'll see the bus mismatch since the receive tuple changes).

Split Operation (N=4)

A 4-element block at address (as=1, ptr=0) is split into two 2-element blocks. The parent block is received from the bus; the two child blocks are sent.

Merge Operation (N=4)

Two 2-element blocks are merged back into one 4-element block. Direction is reversed: children are received, parent is sent.

Adapter Bus Interactions

Each adapter row generates 3 bus interactions: one for the parent block and one for each child half.

Split vs Merge

In a split (is_split=1), the adapter receives the parent block and sends two child blocks. The direction multiplier is +1.

In a merge (is_split=0), the adapter receives two child blocks and sends the parent block. The direction multiplier is -1, flipping send/receive roles.

For a split, left_ts = right_ts (both children inherit the parent's timestamp). For a merge, parent_ts = max(left_ts, right_ts).
