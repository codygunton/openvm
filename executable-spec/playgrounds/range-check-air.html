Range Check AIR

A range check proves a value lies in [0, max). This is a two-AIR system: a Sender AIR holds values to check, and a Range Checker AIR holds a fixed preprocessed lookup table of all valid values. They communicate via a bus using the LogUp protocol.
New: Preprocessed Trace

The Range Checker has a preprocessed column fixed by the verifying key. It contains [0, 1, ..., max-1]. The prover cannot change it.

New: Bus as constraint mechanism

This AIR has zero polynomial constraints. The range check is enforced entirely through the bus. The Sender puts each value on the bus. The Checker absorbs values using its preprocessed table. If a sent value doesn't appear in the table, no row can absorb it, so the cumulative sum cannot reach zero — the proof is rejected. The bus balance is the constraint.

Preprocessed Trace (fixed by verifying key)

This table is not created by the prover. It is fixed when the circuit is compiled and committed in the verifying key. The prover cannot modify it. It contains every valid value in [0, range_max).

The Sender's main trace holds values to check. The Checker's main trace holds multiplicity counts — how many times each preprocessed row was looked up. The bus carries values between them.
