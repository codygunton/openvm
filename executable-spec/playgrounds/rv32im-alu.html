RV32IM ALU

The BaseAluCoreAir handles all five basic ALU operations in a single chip: ADD, SUB, XOR, OR, AND. Instead of five separate AIRs, it uses one-hot opcode flags — exactly one of five boolean flags is set per row. The carry chain handles ADD/SUB while XOR/OR/AND use the BitwiseOperationLookupBus.
One-Hot Opcode Flags
Five boolean columns: add_flag, sub_flag, xor_flag, or_flag, and_flag. Exactly one must be 1. This lets a single AIR handle multiple operations: each constraint is multiplied by its flag, so it only activates for the right opcode.
BitwiseOperationLookupBus
For XOR/OR/AND, the result is verified by looking up (x, y, x⊕y) in a precomputed table. For ADD/SUB, the same bus does range checking by sending (a[i], a[i]) (since a⊕a = 0).

Constraints
  • C1–C4 Limb carry equation ADD: b[i]+c[i]+carry[i-1] − a[i] − carry[i]*256 = 0
    SUB: a[i]+c[i]+carry[i-1] − b[i] − carry[i]*256 = 0
    XOR: a[i] − (b[i] ⊕ c[i]) = 0
    OR: a[i] − (b[i] | c[i]) = 0
    AND: a[i] − (b[i] & c[i]) = 0     all rows
  • C5–C8 Carry is boolean (ADD/SUB only) carry[i] * (1 − carry[i]) = 0 all rows
  • C9 Flag sum = 1 add + sub + xor + or + and = 1 all rows
  • C10 Each flag is boolean flag * (1 − flag) = 0, for each flag all rows

Core Columns (17) & Constraint Evaluation

Edit a[i] and carry[i] cells to see which constraints break. 0 = satisfied, nonzero = violated. Modified cells are highlighted.

Bus Interactions

For ADD/SUB, the bus sends (a[i], a[i], 0) for range checking. For XOR/OR/AND, the bus sends (b[i], c[i], b[i]⊕c[i]) to verify the bitwise operation.
