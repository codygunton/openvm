Crypto: Elliptic Curve (Weierstrass)

The WeierstrassChip handles elliptic curve point operations over short Weierstrass curves: EC_ADD_NE (point addition, P1 ≠ P2) and EC_DOUBLE (point doubling). These are the core operations behind ECDSA signature verification used in Ethereum transactions. The chip uses a FieldExpressionCoreAir that encodes the intermediate values (lambda, x3, y3) as witnesses and constrains the algebraic relations.

This playground uses a small prime p = 97 for visual clarity. In production, secp256k1 uses a 256-bit prime, but the AIR structure is identical.
ECDSA and the zkVM
Every Ethereum transaction is signed with ECDSA over the secp256k1 curve. Verifying a signature requires point addition and doubling — exactly the operations this chip constrains. The prover provides lambda and the result point as witnesses; the verifier checks the algebraic relations hold modulo p. This is how OpenVM proves Ethereum signature verification inside a ZK proof.
Adapter + Core Pattern
Like all OpenVM chips, the Weierstrass chip follows the Adapter/Core split. The Rv32VecHeapAdapterAir handles memory reads (loading point coordinates) and writes (storing the result point). The FieldExpressionCoreAir constrains the field arithmetic — divisions become witness multiplications (e.g., constraining lambda * (x2 - x1) = y2 - y1 instead of computing lambda directly).
