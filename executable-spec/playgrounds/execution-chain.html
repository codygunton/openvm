Execution Chain

A program in OpenVM is a chain of execution states connected by the execution bus. Each instruction chip receives the current state (pc, timestamp) and sends the next state. The VmConnectorAir closes the cycle. The program bus verifies that each instruction matches the committed program ROM.
Key Concepts
New: Execution Bus Cycle

The execution bus is a permutation-check bus. Every (pc, ts) tuple that is sent must be received exactly once. Instruction chips receive (from_pc, from_ts) and send (to_pc, to_ts). The VmConnectorAir closes the cycle by connecting the last instruction's output back to the system.

New: Program Bus (Lookup)

The program bus is a lookup bus. The ProgramAir publishes all instruction tuples from the ROM. Each instruction chip looks up its (pc, opcode, operands) to verify it is executing the correct instruction at the correct PC.

New: VmConnectorAir

A tiny 2-row AIR that bootstraps and closes the chain. Row 0: sends (initial_pc, 1) to start execution. Row 1: receives (final_pc, final_ts) when the TERMINATE instruction runs.

Execution Bus Ledger

Every send must be matched by exactly one receive. Matched = valid, Unmatched = constraint violated.

Program Bus Lookups

Each executing instruction must match an entry in the ROM. Found = valid, Not found = constraint violated.
