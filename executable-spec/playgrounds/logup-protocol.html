LogUp Protocol

The LogUp protocol proves that bus interactions balance across AIRs without sorting. After the prover commits to the main trace, random challenges α, β are sampled. The prover computes after-challenge trace columns (perm[0] = chunk₀, perm[1] = φ) that the verifier checks with polynomial constraints.
Key insight

The per-AIR polynomial constraints always pass — the prover computes the after-challenge trace to satisfy them. Soundness comes from the cross-AIR check: the prover cannot force Σφ[last] = 0 unless the sent and received multisets actually match (by Schwartz-Zippel over random α, β).

Sender AIR send, count = +1

Columns are exactly the witness polynomials: main[0] = val, perm[0] = chunk₀, perm[1] = φ. 0 = constraint satisfied, — = selector off.

Checker AIR recv, count = −mult

prep[0] = counter (fixed by VK), main[0] = mult, perm[0] = chunk₀, perm[1] = φ. Rows with mult=0 are dimmed.

C4: Cross-AIR Cumulative Sum Check (exposed value)

Why do C1–C3 always pass? The prover sets perm[0] = count / (α + msg + β) (satisfying C1) and perm[1] as a prefix sum of perm[0] (satisfying C2, C3). These are honest computations. The soundness is in C4: the prover cannot make Σφ[last] = 0 unless the multisets match. Schwartz-Zippel guarantees this over random α, β.

Note: The real protocol uses FF4 (degree-4 extension) for perm columns and challenges. See protocol/logup.py.
