Keccak-256

Keccak-256 is Ethereum's hash function, used for state proofs, transaction hashing, and address derivation. In OpenVM, it's a hash accelerator chip — a single instruction triggers a multi-row AIR computation. Each Keccak-f permutation takes 24 rows (one per round), and a hash may need multiple permutations for long inputs.
Key Concepts
Multi-Row Instruction
Unlike ALU instructions (1 row = 1 instruction), Keccak uses 24 rows per permutation block. The execution bus interaction only fires on the first row (is_first_round). Rows 1–23 are "continuation" rows with no opcode.
Sponge Construction
Keccak uses a sponge: the 1600-bit state has a 1088-bit rate (absorb input here) and a 512-bit capacity (never directly touched). Each block: XOR input into rate → apply Keccak-f → repeat. Final squeeze extracts the 256-bit hash from the rate.
XOR Absorption
Input bytes are XOR'd into the sponge state via the BitwiseOperationLookupBus. Each XOR is verified by looking up (state_byte, input_byte, result_byte) in the precomputed table.

Input Processing

Input is converted to bytes, then padded to fill a 136-byte block (the sponge rate). Padding follows the 10*1 rule: 0x01 ... zeros ... 0x80.

Sponge State (1600 bits)

The full Keccak state is 200 bytes (1600 bits). Only the rate portion receives input via XOR. The capacity is never directly written — it provides security.

Keccak-f Permutation (24 Rounds)

Each permutation block spans 24 rows in the AIR trace. Round 0 carries the opcode (execution bus fires). Round 23 is where the digest is extracted (memory write). Rounds 1–22 are continuation rows — no bus interactions.
