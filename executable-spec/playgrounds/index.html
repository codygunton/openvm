OpenVM AIR Playgrounds

Interactive explorers for the polynomial constraints in OpenVM's STARK proving system. Edit witness values, break constraints, see why it works.
Examples
Simplified AIRs that introduce core concepts one at a time.

1. Fibonacci AIR

The simplest AIR: two witness columns, five polynomial constraints, three selectors. Edit any trace cell to see which constraints break and why.

2. Range Check AIR

Introduces preprocessed traces and bus interactions. Two AIRs (Sender + Checker) communicate through a shared bus to prove values lie in a range.

3. LogUp Protocol

How bus interactions actually work: random challenge compression, after-challenge trace columns, and the cross-AIR cumulative sum check that ties it all together.

4. Limb Arithmetic AIR

How 32-bit operations work in a 31-bit prime field: limb decomposition, carry propagation, and range checks. The foundation of all RISC-V instruction chips.

5. Adapter/Core Pattern

How instruction chips split into reusable Adapters (memory + execution bus) and swappable Cores (arithmetic). The VmAirWrapper column layout of a real ADD chip.

6. Memory Bus (Offline Checker)

The timestamp-ordered memory protocol: how reads and writes generate send/receive pairs, and how the boundary chip closes the bus.

7. Execution Chain

How the execution bus, program bus, and VmConnectorAir chain instructions into a complete program execution cycle.

RISC-V (RV32IM)
The actual instruction chips that execute RISC-V programs inside OpenVM. These are the AIRs that prove Ethereum transactions.

8. ALU (ADD/SUB/XOR/OR/AND)

The BaseAluCoreAir: five operations multiplexed in one chip via one-hot opcode flags. Carry chain for ADD/SUB, bitwise lookup bus for XOR/OR/AND.

9. Shift (SLL/SRL/SRA)

Bit shifts decomposed into limb_shift (whole bytes) and bit_shift (intra-byte), each encoded as one-hot markers. Carry propagation between limbs.

10. Multiply (MUL/MULH)

Schoolbook polynomial multiplication over 8-bit limbs with carry. MULH extends to upper 32 bits with sign extension.

11. Divide/Remainder (DIV/REM)

The most complex RV32IM chip: verify b = c*q + r via multiplication, prove r < c, handle signed division and zero-divisor edge cases.

12. Branch (BEQ/BNE/BLT/BGE)

Equality via inverse-witness markers, less-than via MSB signed field manipulation and diff_marker scanning. Controls PC flow.

13. Load/Store (LW/LH/LB/SW/SH/SB)

Byte and halfword masking with alignment shifts. Loads extract and optionally sign-extend; stores merge into existing data.

14. Jump (JAL/JALR/LUI/AUIPC)

PC-relative and register-indirect jumps. LUI/AUIPC load upper immediates. JALR sign-extends a 12-bit immediate and clears the LSB.

15. Keccak-256

Multi-row hash accelerator: 24 rows per Keccak-f permutation, sponge construction, XOR absorption via bitwise lookup bus. Used for Ethereum state proofs.
