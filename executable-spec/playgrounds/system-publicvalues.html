System: Public Values

The PublicValuesCoreAir handles the PUBLISH instruction — it reads a value from memory and commits it to a specific slot in the proof's public values array. The constraint system verifies that each published value matches the corresponding public value that the verifier will see. Used in single-segment proofs (not continuations).
Key Insight: Proof Outputs
Public values are the only data the verifier sees besides the proof itself. They form the bridge between the private computation and the public claim. The PUBLISH instruction lets the guest program declare: "the value at memory address X should be visible as public_values[i]."
Encoder-Based Selectors
Instead of N one-hot columns to select which public value slot, the AIR uses a multivariate Lagrange encoder that compresses N selectors into ~log(N) columns. The encoder variables satisfy range constraints and their Lagrange evaluation selects exactly one slot.

Public Values Array

The proof's public values as the verifier sees them. Each PUBLISH instruction writes to one slot. Green border = assigned by a trace row. Red = value mismatch with trace.

Trace Table (PublicValuesCols)

Each row is one PUBLISH instruction. Edit value or index to break constraints. 0 = satisfied, — = selector inactive, nonzero = violated. Modified cells are highlighted.

Constraint Evaluation

C3 is the critical constraint: each row's value must equal public_values[index]. If a row's value doesn't match the public value at its index, the proof is invalid.

Bus Interactions

The adapter reads two operands from memory: the value to publish and the index. The execution bus advances PC by 4. The program bus verifies the PUBLISH opcode.
