System: Program Bus

The ProgramAir implements the instruction ROM of the VM. It publishes every instruction in the compiled program as a lookup table on the ProgramBus. When an instruction chip executes an instruction, it performs a lookup against this table to prove it is executing a valid instruction at the correct PC with the correct operands. This prevents the prover from executing unauthorized instructions.
Key Concepts
Instruction ROM (Preprocessed Trace)

The program is a fixed table committed at verifying key generation time. Each row holds one instruction: (pc, opcode, a, b, c, d, e, f, g). These 9 columns form the cached (preprocessed) trace. The only runtime column is exec_freq.

LookupBus Mechanism

The ProgramBus is a LookupBus. The ProgramAir adds each instruction as a key with multiplicity = exec_freq. Instruction chips call lookup_key() to consume one execution. If total lookups do not match total exec_freq for every instruction, verification fails.

Partitioned AIR

The ProgramAir uses PartitionedBaseAir: the 9 instruction columns are cached main (committed once, reused), while exec_freq is the common main (varies per execution). Total width = 10 columns.

Instruction Table (Program ROM)

Each row is one instruction in the compiled program. The exec_freq column shows how many times the instruction is executed. Edit any cell to explore. Modified cells are highlighted. The instruction columns (PC through g) are preprocessed — fixed at VK generation time.

Execution Frequency

Bar chart showing how many times each instruction executes. Instructions inside loops have higher frequency. Padding rows have freq=0.

Bus Lookup Ledger

Each execution step sends a lookup to the program bus. The instruction table publishes each key with multiplicity = exec_freq. The bus balances when total lookups = total published for every instruction tuple.

What If: Remove an Instruction

Toggle a row off to simulate removing it from the ROM. If the execution trace still references that instruction, the bus lookup will fail — the prover tried to execute an instruction not in the program.
