System: Phantom Opcodes

The PhantomAir handles phantom instructions — operations that the prover can execute freely with zero additional constraints. The constraint system only sees a NOP: advance PC by 4 and increment timestamp by 1. Everything else the phantom does (loading hints, debugging, profiling) is invisible to the verifier.
Key Insight
Phantom instructions are "free" operations — they affect execution but add NO constraints beyond PC increment. The prover can do arbitrary computation in phantom handlers without adding constraints. This is safe because phantom operations only affect prover-side state, not the public computation.
ExecutionBridge
The only bus interaction: ExecutionBridge.execute_and_increment_or_set_pc(). It receives (pc, timestamp) and sends (pc + 4, timestamp + 1). The operands (a, b, c) are columns but are unconstrained — the verifier never checks their values.

Constraint System View

Regardless of the discriminant selected, the constraint system only verifies two things: pc_next = pc + 4 and timestamp advances by 1. The discriminant value stored in operand c is completely invisible to the verifier.

Constraint Evaluation

The execution bridge checks that consecutive phantom instructions form a valid chain: each row's (pc_next, ts_next) must equal the next row's (pc, ts).
