Adapter / Core Pattern

Every instruction chip in OpenVM is built from two independent pieces: an Adapter that handles system bus interactions (memory reads/writes, execution state, program lookup) and a Core that handles instruction-specific arithmetic. They're combined via VmAirWrapper, which concatenates their columns into a single trace row.
New: Column Split

A trace row is [adapter_cols | core_cols]. The adapter and core have separate constraint sets. The core returns results that the adapter uses for its bus interactions.

New: Reusable Adapters

The same adapter works for ADD, SUB, XOR, OR, and AND. Only the core changes. The adapter doesn't know what arithmetic the core performs -- it just reads two register values and writes one result.

Constraints (Core)
  • C1 Limb 0 arithmetic b[0] + c[0] - a[0] - carry[0] × 256 = 0 all rows
  • C2 Limb 1 arithmetic b[1] + c[1] + carry[0] - a[1] - carry[1] × 256 = 0 all rows
  • C3 Limb 2 arithmetic b[2] + c[2] + carry[1] - a[2] - carry[2] × 256 = 0 all rows
  • C4 Limb 3 arithmetic b[3] + c[3] + carry[2] - a[3] - carry[3] × 256 = 0 all rows
  • C5 Carry 0 boolean carry[0] × (1 - carry[0]) = 0 all rows
  • C6 Carry 1 boolean carry[1] × (1 - carry[1]) = 0 all rows
  • C7 Carry 2 boolean carry[2] × (1 - carry[2]) = 0 all rows
  • C8 Carry 3 boolean carry[3] × (1 - carry[3]) = 0 all rows
  • C9 Exactly one opcode flag add + sub + xor + or + and = 1 all rows
