Crypto: Modular Field Arithmetic

The FieldExpressionCoreAir proves modular arithmetic operations (ADD, SUB, MUL, DIV) over large prime fields like secp256k1. The modulus is a runtime parameter set during SETUP — the same circuit can prove arithmetic over ANY prime field. Values are represented as 32-byte limb arrays and verified using carry-chain constraints and quotient witnesses.
Runtime-Configurable Modulus
Unlike hardcoded circuits, OpenVM's modular arithmetic chip accepts the modulus at SETUP time. The first row of each trace is a SETUP instruction that locks in the modulus p. All subsequent rows verify operations mod p. This means one circuit handles secp256k1, BN254, BLS12-381, or any other prime field.
Witness-Based Verification
The prover provides the result and a quotient q as witnesses. The constraint checks: a op b - result - q * p = 0 at the limb level, using carry propagation to handle overflow. The verifier never computes the modular operation directly — it only checks the algebraic identity.
Carry-Chain Arithmetic
256-bit arithmetic is done limb-by-limb (8-bit limbs). When adding two limbs, the sum may exceed 255, producing a carry that propagates to the next limb. Each carry is range-checked to ensure soundness.

How It Works: Runtime Modulus

Why is the modulus not hardcoded?

Elliptic curve cryptography uses different prime fields: secp256k1 for Bitcoin/Ethereum, BN254 for Ethereum pairings, BLS12-381 for newer protocols. Instead of building a separate circuit for each, OpenVM uses FieldExpressionCoreAir — a generic arithmetic circuit parameterized by any prime modulus.

The SETUP instruction writes the modulus into the trace as the first row. The constraint system reads p from this setup row and uses it in the identity expr(inputs) - output - q * p = 0. The quotient q is provided by the prover as a witness. Range checks ensure all values are properly reduced.

ADD/SUB share one chip (ModularAddSub) with flags is_add and is_sub. MUL/DIV share another (ModularMulDiv) with flags is_mul and is_div. IS_EQ uses a separate chip (ModularIsEqualCoreAir) that proves b == c or b != c while also proving both operands are less than p using an lt_marker array.
